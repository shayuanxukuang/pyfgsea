# Contributing to PyFgsea

- Keep each change focused on one reviewable behavior.
- Add tests for changes to public behavior.
- Keep private helpers out of the public API.
- Do not ship dummy, pass-only, or silent no-op functions.
- Use short error messages that identify the failed condition.
- Read the package version from `Cargo.toml`.
- Record numerical defaults and reference-package versions.
- Keep paper reproduction separate from current-reference benchmarks.
- Run `make check` before opening a pull request.
