# PyFgsea 0.2.0 manuscript impact decision

## Decision

The current evidence is most consistent with **a numerical and methods correction whose central software-concordance conclusion remains intact**. It is not a clean “software update only” case because the Figure 2 input scale, dataset description, assignment mixture, and trajectory wording require substantive correction. It is also not evidence that the paper's main conclusion has failed: the formal legacy lane reproduces the published Figure 1 values, and the current lane retains very high agreement with the newer R reference.

The practical category is therefore closest to **B: update affected numbers and text while retaining the main conclusion**. The journal should be given the corrected Figure 1, Figure 2 caption and Methods text, and a compact table distinguishing the publication and current software lanes. Whether the journal calls this an Author Correction or another correction notice is an editorial decision.

## What the formal results establish

The publication comparison and the current comparison answer different questions:

- **Publication lane:** PyFgsea 0.1.4 versus R fgsea 1.32.2 reproduces the reported 100-pathway publication-main values after rounding. ES RMSE is `3.84e-16`; NES Pearson/Spearman/RMSE are `0.999967`, `0.999676`, and `0.01333`; and transformed-p Pearson/Spearman/RMSE/median absolute difference are `0.997199`, `0.988318`, `0.16960`, and `0.04672`.
- **Current lane:** PyFgsea 0.2.0rc8 versus R fgsea 1.38.0 gives ES RMSE `3.21e-16`; NES Pearson/Spearman/RMSE are `0.999952`, `0.999652`, and `0.01567`; and transformed-p Pearson/Spearman/RMSE/median absolute difference are `0.999069`, `0.996628`, `0.11826`, and `0.01916` on the same 100-pathway scenario.
- **Tie-heavy case:** in the separate 60-pathway case, the legacy lane has ES RMSE `0.07231` and NES RMSE `0.29868`, whereas the current lane has ES RMSE `3.25e-16` and NES RMSE `0.01558`. This is a specific 0.1.4 limitation corrected in 0.2.0rc8, not a property of the publication-main input.
- In both lanes and both formal scenarios, the top-10 absolute-NES pathway set is identical between PyFgsea and R. FDR-set Jaccard values are `0.9565` on the publication input and `0.9444` in the tie-heavy case. These two scenarios do not replace the older six-regime supplement.

The dual-lane results therefore support a narrow statement of high concordance on the tested inputs. Correlation and set overlap should not be described as proof of algorithmic identity, universal equivalence, or biological correctness.

The completed current numerical evidence is for `0.2.0rc8`. It may be relabelled as the final `0.2.0` result only if the release is shown to contain the same numerical implementation and the installed release artifact passes the corresponding functional checks.

## Figure 2 corrections

Figure 2 should be described as a descriptive reassembly of a processed GSE155254 subset:

- The input contains **3576 erythroid-subset cells from two samples**.
- Public assignment tables match **2097 control** and **816 gata307mut** cells; **663 cells are unmatched**. The figure pools these groups and is not a control-versus-mutant analysis. Cell counts are not biological replicate counts.
- The frozen object's uniform `Disease` field resulted from sample-name inference and conflicts with the public per-cell assignments; it should not be reported as a true cell-level condition.
- UMAP coordinates and DPT were **precomputed**. The figure does not independently infer or orient a lineage.
- The frozen object contains scaled, clipped `adata.X` values and no separate raw or named log1p layer. Panel D ranks genes from scaled `adata.X`, so the manuscript's “log1p-normalized expression” wording is incorrect for this figure.
- Panel B is an argmax grouping over population z scores for CD34, MKI67, and HBB. It is a marker-dominant visual grouping, not a cell-type annotation.
- Panel C uses scaled HBB and MKI67 values with a 151-cell centered rolling mean. It is descriptive.
- Panel D uses 500-cell windows, a 50-cell step, 2000 NES permutations, standard scoring, exact pathway sizes, no binning, and no cross-window NES cache. All 62 by 43 pathway-window results resolved. Benjamini-Hochberg adjustment is within each window only.

Suggested caption:

> Rolling-window GSEA in a 3576-cell erythroid subset from GSE155254. Panels A and B use precomputed UMAP coordinates, and cells are displayed by precomputed DPT. Panel B shows a descriptive dominant-marker grouping based on CD34, MKI67, and HBB rather than formal cell-type annotations. Panel C shows scaled HBB and MKI67 values smoothed with a 151-cell centered rolling mean. Panel D shows Heme Metabolism and E2F Targets NES profiles from 500-cell windows advanced in 50-cell steps. Filled points indicate Benjamini-Hochberg adjusted p<0.05 across pathways within the same window; this does not provide trajectory-wide error control. The pooled subset contains 2097 control-assigned, 816 gata307mut-assigned, and 663 unmatched cells and is not a control-versus-mutant comparison.

## Text that should not be carried into the correction

The `1.9-fold`, `7.47-fold`, `1.35 s`, and memory-comparison values are historical. The formal current run does not measure the same work under a common timing and memory scope, so none of these values should be presented as 0.2.0 performance. The GSEApy and BlitzGSEA panels should likewise be removed from the revised Figure 1 caption unless those tools are rerun under matched conditions.

The old worst-window transformed-p correlation and six-regime overlap ranges should not be replaced by a newly selected worst case. They can return only if the original selection rule and all planned regimes are rerun. Deep-tail superiority should not be inferred from a lower reporting floor.

## Suggested corrected abstract wording

> The published comparison used PyFgsea 0.1.4 with R fgsea 1.32.2. On the matched publication input, the formal reproduction showed machine-precision ES agreement, NES Pearson r=0.99997, and transformed nominal-p Pearson r=0.99720. A separate current comparison of PyFgsea 0.2.0rc8 with fgsea 1.38.0 showed machine-precision ES agreement, NES Pearson r=0.99995, and transformed nominal-p Pearson r=0.99907. A predeclared tie-heavy case revealed a limitation of 0.1.4 that is corrected in 0.2.0rc8. Rolling-window profiles use Benjamini-Hochberg adjustment across pathways within each window and are intended as descriptive summaries rather than trajectory-wide discoveries.

## Interpretation boundaries

The manuscript should keep the following distinctions visible in ordinary scientific prose:

- never pool the 0.1.4/1.32.2 and 0.2.0/1.38.0 results;
- do not treat cells as independent donors or the pooled assignments as a case-control design;
- do not infer lineage direction, mechanism, or causality from precomputed DPT and pathway profiles;
- do not treat within-window adjustment as trajectory-wide multiplicity control;
- do not generalize two benchmark scenarios to every input type;
- do not use correlation alone as a claim of equivalence; report absolute differences and the tested scope;
- preserve the predeclared tie-heavy case rather than selecting only favorable examples after viewing results.

This note was prepared from the manuscript source, formal numeric tables, the Figure 2 assembly metadata, the frozen H5AD structure, and the public assignment tables. No figure image inspection was used.
