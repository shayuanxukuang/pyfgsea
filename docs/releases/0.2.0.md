# PyFgsea 0.2.0 release note

Status: unreleased. The current distribution version is `0.2.0rc6`; final
`0.2.0` artifacts have not been published. Technical results for earlier
candidates are listed in the
[release-candidate history](0.2.0-rc-history.md).

## What changed

PyFgsea 0.2.0 updates the numerical contract used by the high-level API:

- `mode="aligned"` is the default estimator mode.
- `score_type="std"` is the default score type.
- Aligned mode uses exact pathway-size nulls (`bin_width=0`).
- Gene-ID ordering makes tied ranks deterministic.
- Null estimation reports explicit unresolved and failure states instead of
  silently omitting affected pathways.
- The result table includes tail depth, error, termination, approximation,
  pathway-size, ranking, and algorithm-revision diagnostics.
- Regression coverage includes the fgsea 1.38 behavior associated with
  upstream issue 151.

The low-level `build_tail_curve` and `query_tail_curve` functions remain
available but are deprecated. They implement the approximate
`legacy-empirical-tail-v1` helper, not the aligned multilevel estimator.
Incompatible score-type or sign queries are rejected.

Trajectory analysis now uses maintained plotting functions and the following
defaults: `window_size=500`, `step=50`, `nperm_nes=2000`,
`score_type="std"`, exact pathway sizes, NES caching off, and a stable master
seed with ranking-bound streams. Calling `plot_pathway_dynamics` without a
pathway list raises `ValueError`.

Core runtime dependencies are separated from the optional `trajectory` extra.
The never-implemented `run_scanpy` symbol is no longer advertised. Rust
formatting, Rust tests, Ruff, and mypy run as independent checks.

Release checks cover:

1. source and Rust tests from a clean worktree;
2. an annotated release-candidate tag that resolves to the tested commit;
3. an sdist built from that source;
4. a wheel built from the verified sdist;
5. installation of that wheel in a clean environment;
6. checks of the installed version and native core;
7. installed-wheel tests on the supported platforms; and
8. SHA-256 records for the source, sdist, wheel, installed core, inputs, and
   outputs.

`Cargo.toml` is the single source for the Rust crate and Python distribution
version. Maturin supplies that version to Python package metadata.

## Compatibility with 0.1.4

The 0.2.0 defaults are intentionally different from 0.1.4:

| Setting | 0.1.4 default | 0.2.0rc6 default |
| --- | --- | --- |
| high-level score type | `two_sided_abs` | `std` |
| estimator contract | implicit legacy behavior | `mode="aligned"` |
| pathway-size binning | `None` | `0` (exact size) |
| trajectory `step` | `100` | `50` |
| trajectory `nperm_nes` | `100` | `2000` |
| trajectory `bin_width` | `10` | `0` (exact size) |
| trajectory NES cache | on | off |
| trajectory RNG | `seed + window_id` | stable ranking-bound streams |

`score_type="two_sided_abs"` remains available for a bounded legacy-like
absolute-tail calculation. It is marked approximate and is not equivalent to
R `fgseaMultilevel(scoreType="std")`.

No 0.2.0 option set is claimed to reproduce 0.1.4 byte-for-byte. Reproduction
of the published comparison uses the fixed 0.1.4 / R fgsea 1.32.2 lane. Tests
of the repaired implementation use the separate 0.2.0 / R fgsea 1.38.0 lane.

## Migration

For new analyses, specify the numerical contract explicitly:

```python
result = pyfgsea.run_gsea(
    data=ranks,
    gmt=pathways,
    gene_col="gene",
    score_col="score",
    mode="aligned",
    score_type="std",
    bin_width=0,
    seed=42,
)
```

When updating a 0.1.4 workflow:

1. record the previous score type, pathway-size handling, seed, and trajectory
   settings;
2. choose aligned or approximate behavior explicitly;
3. keep unresolved and failed rows in the comparison output;
4. compare ES, NES, p-values, adjusted p-values, pathway overlap, runtime, and
   memory before replacing saved results; and
5. record the PyFgsea version and `algorithm_revision` with each output.

Install single-cell and plotting dependencies with:

```bash
python -m pip install "pyfgsea[trajectory]"
```

The Python API does not currently accept an `n_threads` keyword.

## Reproducing the paper

Paper reproduction keeps two named reference lanes:

| Lane | PyFgsea | R | Bioconductor | fgsea | Use |
| --- | --- | --- | --- | --- | --- |
| `legacy_publication` | 0.1.4 | 4.4.3 | 3.20 | 1.32.2 | Reproduce the comparison declared in the paper |
| `current_conformance` | 0.2.0rc6 | 4.6.0 | 3.23 | 1.38.0 | Test the repaired implementation against the current reference |

The lanes are not interchangeable. Each run must record its lane, score type,
pathway universe, size filters, sample size, epsilon, seeds, result mode, and
unresolved/failure counts.

The [Figure 1 dual-lane protocol](../../repro/figure1_dual_lane/README.md)
uses four committed rank/GMT files: a reconstructed publication scenario and a
separately labelled ties scenario. Cross-platform functional tests compare the
committed bytes and their semantic invariants. They do not use a predeclared
input SHA-256 value as a pass condition. Run records calculate SHA-256 values
for the files used by each run.

Figure 2 uses the recorded parameters in
`repro/figure2_gse155254/figure2_parameters.json`:

- `window_size=500`;
- `step=50`;
- `nperm_nes=2000`;
- `score_type="std"`;
- `pathway_size_policy="exact"`, implemented by `mode="aligned"` with
  `bin_width=0`; and
- NES caching disabled.

A reproducible Figure 1 or Figure 2 result starts from a clean tagged checkout
and a checked installed wheel. Its record includes the full commit, tree,
annotated tag, source/sdist/wheel sequence, installed native core,
installed-wheel test result, reference environment, exact parameters,
commands, inputs, outputs, and their SHA-256 values.

Reference definitions are in `reference_manifest.json` and
[fgsea-1.38-alignment.md](../fgsea-1.38-alignment.md).

## Known limitations

- Final `0.2.0` PyPI, GitHub Release, and Zenodo artifacts are not yet
  published.
- Source-level success does not replace sdist, wheel, installed-wheel,
  cross-platform, or reference-container checks.
- Figure 1, Figure 2, supplementary-result, and manuscript comparisons remain
  separate calculations.
- The reconstructed publication input matches the recovered generator and
  pathway definitions, but the unavailable historical temporary file cannot
  be checked for byte identity.
- Fast mode and legacy empirical-tail helpers are approximate.
- Peak-memory sampling and runtime measurements are hardware-specific.
- The Figure 1 dual-lane pipeline does not reproduce separate GSEApy or
  BlitzGSEA panels.
- Any skipped R comparison or unresolved/failure state remains incomplete and
  must be reported.

GitHub Actions artifacts are temporary transport. Copy the exact checked
bundles, OCI records, and SHA-256 manifests to the GitHub Release and Zenodo
before the temporary files expire.
