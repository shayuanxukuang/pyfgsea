# PyFgsea 0.2.0 release note

Status: unreleased; implementation and the required source-level regression matrix are complete, while artifact-level conformance and manuscript recalculation are incomplete.

Closure state:

```text
SOURCE_LEVEL_REPAIR_ACCEPTED
ARTIFACT_AND_MANUSCRIPT_CLOSURE_PENDING
```

PyFgsea 0.2.0 is the release boundary for the fgsea 1.38.0 statistical repair. The package version is sourced from `Cargo.toml` by maturin; `pyproject.toml` declares a dynamic version. A source checkout reads that Cargo version, while an installed wheel reads its distribution metadata. This removes the prior independent Python, Rust, and import-time version strings.

The release distinguishes the historical PyFgsea 0.1.4/R 4.4.3/fgsea 1.32.2 publication lane from the PyFgsea 0.2.0/R 4.6.0/fgsea 1.38.0 conformance lane. R reference scripts now require and verify an explicit lane instead of using whichever fgsea package is installed. Missing benchmark inputs also fail closed rather than generating synthetic or dummy evidence.

Statistical outputs from 0.1.x and 0.2.0 must not be pooled without recording the implementation version and reference lane. After the final Rust-core rebuild, 7 Rust unit tests passed. The full non-slow/non-external `tests/` source suite passed 236 tests, skipped the one optional exact-R subprocess test in the generic Python environment, and deselected 13 explicitly slow or external tests. The exact reference file was then run separately against R 4.6.0/Bioconductor 3.23/fgsea 1.38.0 and passed both tests, so all 53 tests in the eight required regression files have executed successfully under their declared environments. The Figure 1 evidence pipeline additionally passed its 7 lightweight fail-closed tests. These local runs are not frozen-image or manuscript-artifact receipts.

The historical `pyfgsea-0.1.4` wheel has distribution metadata version 0.1.4 but declares `pyfgsea.__version__ = "0.1.3"` and Cargo version 0.1.3. The legacy evidence runner treats this as a historical packaging mismatch to verify, not a value to rewrite. A fail-closed dual-lane Figure 1 suite now exists at `repro/figure1_dual_lane/`; it binds wheels, native cores, R environments, inputs, raw pathway rows, and derived metrics, but it has not yet produced an accepted dual-lane receipt.

An explicit Figure 2 parameter contract was accepted on 2026-09-01: 500-cell windows, 50-cell steps, 2000 NES permutations, `score_type=std`, exact pathway sizes (`mode=aligned`, `bin_width=0`), and no cross-window NES cache. The versioned contract is `repro/figure2_gse155254/author_parameter_contract.json`. This parameter acceptance is not manuscript or publication acceptance. The earlier non-overwriting candidate resolved all 2666 pathway-window rows and passed its hash and independent-BH checks, but it remains unbound because it was produced from a dirty source tree and an unverified local core. The formal runner now requires a clean annotated tag, an external output directory, and the exact wheel/native-core receipt from the sdist-to-wheel verifier. Manuscript values remain historical until that formal run and the checklist in `docs/fgsea-1.38-alignment.md` pass; the legacy lane, reference OCI builds, artifact-level conformance matrix, Figure 1, supplement, and formal Figure 2 receipt are still outstanding.

The evidence-only workflow `.github/workflows/pyfgsea-0.2.0-artifacts.yml` defines cross-platform sdist-to-wheel verification and two non-pushing OCI exports. Its action dependencies are pinned to immutable commits and it has read-only repository permission. It has not been executed on GitHub runners and therefore is a definition, not a release receipt.
